## 三、核心发现：记忆提取存在类型梯度

D6 按类型拆分的提取成功率：

| 类型 | 成功率 | 说明 |
|---|---|---|
| 身份/研究偏好 | 22/30 = 0.733 | 系统最稳 |
| 约束/否定 | 13/21 = 0.619 | 中等 |
| 观点/评价 | 8/21 = 0.381 | 明显短板 |
| 交流风格/格式 | 6/18 = 0.333 | 最弱 |

「观点/评价类」是系统性短板，三个评测从不同角度一致印证：

- D2：新增 10 条观点/评价，多漏提
- D3：中段（观点为主）保持率仅 0.2
- D6：观点类偏好多 0/3

根因（与 EVAL_REPORT 附录 E 的 Archival 漏提同源）：`MEMORY_EXTRACTION_SYSTEM` 规则 1「只提取关于用户的事实」，让 LLM 把「观点/评价」（主观看法，非「事实」）判为不提取。

## 四、D6 风格类 variant 生成漂移（数据集 bug）

抽查 0/3 的风格类偏好，发现 variant 被 LLM 改写成了「祈使命令句」而非「偏好陈述」：

- p25「喜欢先给结论再展开分析」→ variant「你能不能先说结论再慢慢解释？」
- p26「回答时喜欢分点列出」→ variant「你可以分点跟我说」
- p27「喜欢回答带具体例子」→ variant「你跟我说的时候能不能带点具体的例子？」

这些祈使句被提取器正确判为「临时的、任务相关的要求」而 NO。语义从「长期偏好」漂移成「临时命令」，属 generate_d6.py 改写 prompt 未约束「陈述式偏好」所致。

### 修复与再诊断

已修：generate_d6.py 改写 prompt 加「陈述式而非祈使命令」约束，并手写 p25-p27 的陈述式 variant。

再诊断发现：修完后提取器能正常提取（不再判 NO），但提取结果与 preference 的 bge 余弦仍卡在 0.6-0.71（阈值 0.72 以下）。例如 p26「回答时喜欢分点列出」被提取成「用户偏好分点列出的回答」（sim=0.694），核心语义保留但「回答时」语境丢失。另有偶发空返回/截断（如 p27 提取成「用户偏好别人回答时附带」被截断）。

这暴露了更深的问题：bge-large-zh-v1.5 对「回答风格/观点」类抽象语义的表示偏弱，导致语义等价但措辞不同的判定余弦偏低，0.72 阈值对这类不鲁棒，与「观点类短板」同源。

## 七、重大发现：推理模型 max_tokens bug（已修复）

诊断 D3 中段时定位到根因，且它解释了一连串历史「LLM 偶发空」现象。

### 根因

deepseek-v4-flash 是推理模型，每次调用先输出 `reasoning_content`（思考），再输出 `content`（答案）。API 的 `max_tokens` 限制两者之和。而 `_llm_extract` 硬编码 `max_tokens=256`，推理过程随机吃 300-500 token，直接超过 256，导致 `content` 被截断成空字符串。

旁证：同一个模型，`_update_summary` 用 max_tokens=512 一直正常，`_llm_extract` 用 256 经常空。

### 修复（两处，均改生产代码）

1. `_llm_extract` 的 max_tokens 256 → 1024
2. `LLMResponseCache.cache_key` 补 max_tokens 参数（原 key 只含 system/user/model/temperature，空结果被缓存污染 1 小时），同步改 openai_compatible_provider 与 anthropic_provider 两处调用。

### 修复后新基线

| 评测 | 修复前 | 修复后 | 提升 |
|---|---|---|---|
| D2 提取召回 | 0.383 | 0.600 | +21.7pp |
| D3 保持率（总计） | 0.433 | 0.667 | +23.3pp |
| D3 中段 | 0.200 | 0.800 | +60pp |
| D6 一致性 | 0.544 | 0.622 | +7.8pp |

### 修复后仍未解决（真实残留）

- D2 分类准确率 0.722：System 肯定式约束（必须/要求）误分 Entity，独立于 max_tokens
- D6 观点/风格类余弦偏低：bge 对抽象语义表示偏弱（见第四节），非 max_tokens 问题
- summary 偶发空：`_update_summary` 用 max_tokens=512，reasoning 长时仍可能空（有 keeping old summary 保护，影响较小）

## 八、D3 评测设计修复（关键信息埋末尾致漏提取）

诊断 D3 短段发现：埋在对话**末尾**的关键信息，因对话结束时未触发 FIFO 压缩弹出，一直留在缓冲区没进提取环节，检索自然找不到（评测设计缺陷，非系统问题）。

修复两处：
1. `generate_d3.py`：后 5 条关键信息从「对话末尾」挪到「中间」，后面补 n_tail 组闲聊把它们顶出 FIFO。
2. `evaluate_d3.py`：跑完 enqueue 后加「收尾 flush」，模拟生产里的 idle 提取，把仍留在缓冲区的消息也提取成记忆。

修复后基线：

| 段 | 修复前 | 修复后 |
|---|---|---|
| 短 20 轮 | 0.500 | 0.900 |
| 中 50 轮 | 0.800 | 1.000 |
| 长 100 轮 | 0.700 | 1.000 |
| 总计 | 0.667 | 0.967 |

剩 1 条（短段「三怪母题」）是提取器偶发漏（LLM 随机性），非评测设计问题。

### D6 阈值结论（补充）

bge 余弦对观点/风格类，「语义等价」与「语义偏了」的余弦在 0.56-0.67 重叠，降阈值会误判（如「偏好反封建版本」0.6725 vs 「持保留意见=值得商榷」0.6758，余弦几乎相同但一个偏一个等价）。故 D6 阈值保持保守（0.72），不接受假阳性；等价但余弦低的记忆实际都在库里，低分不影响系统能力。若要提升 D6 分数，应换判定方式（LLM judge / bge-m3）而非降阈值。
