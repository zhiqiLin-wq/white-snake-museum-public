# D2（L2 提取质量）全程复盘

- 日期：2026-08-22
- 被测系统：`MemoryExtractor.extract`（LLM 提取 + 规则分类）
- 评测脚本：`evaluate_d2.py`（60 条金标准事实：Entity 20 / Archival 20 / System 20）
- 一句话结论：D2 召回 0.533→0.967、分类 0.660→0.983，核心是**用「LLM 直接输出类型」替代「关键词枚举分类」**，并放开长度过滤、扩宽提取 prompt 覆盖。

---

## 一、D2 测什么

**L2 提取质量**：单条用户陈述进来，提取器能不能①提取出语义匹配的记忆（召回率）、②分类正确（分类准确率）、③不乱提垃圾（精确度）。

- 提取召回率 = 语义匹配金标准的事实数 / 总数（有没有漏）
- 分类准确率 = 分类正确 / 被成功提取的事实数（类型对不对）
- 提取精确度 = 提取器输出的记忆里「匹配到金标准」的条数 / 输出总条数（有没有乱提）

---

| 阶段 | 召回率 | 分类准确率 |
|---|---|---|

## 三、失分根因（诊断）

首跑 0.533 召回，28 条漏提，逐条查 statement 长度后分两类：

### 根因 1：statement < 20 字被长度过滤（15 条）

`_MIN_CONTENT_LENGTH=20` 把短 statement 一刀切拦掉。但「我叫知知。」5 字、「别给我发表情符号啊。」10 字，都是有效身份/约束。知知指出「5 个字也可能有重要信息」——**长度不该是"值不值得记"的尺子**。

### 根因 2：提取 prompt 规则太窄（13 条判 NO）

- Archival 漏提：规则 1「只提取关于用户的事实」，把客观知识（"雷峰塔1924年塌"）判成"不是关于用户的"。
- System 漏提：规则 5 只写「否定式拒绝」，肯定式要求（"必须标注出处""按朝代顺序"）没被覆盖。

### 根因 3：分类器关键词枚举脆弱（错类 18 条）

`_classify_memory_type` 用关键词枚举分类，constraint 只含否定词（不要/禁止/别），肯定式约束（必须/要求/标明）漏判。知知点破：**枚举不完**——用户表达约束方式无穷。

---

## 四、改动

### 1. 放开长度过滤
`_MIN_CONTENT_LENGTH` 20 → 1（只过滤空串），噪声交给 `_NOISE_PATTERNS` + LLM 判 NO。

### 2. 扩宽提取 prompt
- 规则 1：加「用户陈述的客观知识/事实（文献出处、版本、年代、地点）也算」。
- 规则 5：加「肯定式要求（必须/要求）也是约束」。
- extract() 里 `len(statement) < 10` 同步放宽到 `< 2`（短身份如"我叫知知"4 字要保留）。

### 3. LLM 直接输出类型（核心）
把分类从「关键词枚举」改成「LLM 提取时直接输出类型」：

- prompt 规则 4 改成输出「类型：内容」，类型四选一 Entity/Archival/System/Working。
- `extract()` 加 `_parse_typed_statement` 解析类型前缀，类型缺失回退 `_classify_memory_type` 规则兜底。
- 规则关键词分类降级为兜底，不再当主力。

---

## 五、蝴蝶效应（改输出格式的连锁）

改 prompt 输出「类型：内容」后，D6 评测脚本直接调 `_llm_extract` 会拿到带「Entity:」前缀的文本，和 preference 比余弦被前缀拖低。已同步适配 `evaluate_d6.py` / `diagnose_d6.py`，加 `strip_type_prefix` 剥前缀。

D6 一致性因此从 0.622 升到 **0.767**（附带收益，0/3 从 4 条归零）。D3 重跑 0.967 无退化。

## 七、精确度（后补的维度）

最初 D2 只测召回 + 分类，漏了「精确度」——提取器有没有乱提垃圾。后补上：

- 精确度 = 提取器输出的记忆里「匹配到金标准」的条数 / 输出总条数。
- 结果 59/60 = 0.983：**提取器几乎不乱提**（60 条输出里只有 1 条对不上金标准，且大概率是措辞差异被判偏，非真乱提）。

## 八、剩余失分（LLM 偶发，每次跑略有不同）

- 漏提、错类各 1 条左右，典型如「不要提供医疗金融建议」（漏提）、「优先原始文献」（错类成 Entity）。
- 非系统缺陷，是 LLM 固有随机性 + bge 对措辞差异敏感（同 D6 的判定问题）。

---

## 九、经验教训

1. **语义分类交给 LLM，别用关键词枚举**：LLM 在提取时已理解语义，输出类型标签是自然的；关键词枚举永远覆盖不全（[[llm-direct-classification]]）。
2. **长度不是"值不值得记"的尺子**：短身份/约束（"我叫知知""别发太长"）也重要，长度过滤只该拦空串，噪声交给内容判断。
3. **改 LLM 输出格式要扫全引用**：D6 评测脚本直接拿 `_llm_extract` 原始输出，格式变了要同步适配，否则余弦被前缀拖低。
